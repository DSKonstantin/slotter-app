# AppMetrica: как смотреть статистику приложения

AppMetrica показывает, что пользователи делают в приложении Slotter: как входят, создают записи, оформляют подписку. Ниже описано, что нужно для работы и где что смотреть.

Приложение в AppMetrica: «Slotter сервис онлайн-записи», ID `6364891`.
Адрес: https://appmetrica.yandex.ru/overview?appId=6364891

---

## Что нужно для работы

1. **Аккаунт Яндекс ID.** Доступ к приложению выдаёт его владелец: Настройка → Управление доступом.
2. **Статистика идёт из приложения, установленного из App Store.** Тестовые сборки (TestFlight) статистику не отправляют. Пока приложение не установлено и не открыто, отчёты пустые.
3. **Данные появляются не сразу.** Приложение отправляет события пачками, а не мгновенно, и AppMetrica может получать их до 7 суток. В отчёте событие показывается по времени, когда оно произошло, поэтому цифры за прошедшие часы и дни могут вырасти задним числом. Если отчёт пустой, проверьте его позже.
4. **Время в отчётах московское.** Период «Сегодня» считается по нему.
5. **В отчётах могут быть тестовые события** команды разработки (`debug_test_event`, `My event`, `My error`). Их нужно игнорировать.

---

## Как найти событие

1. Слева откройте **Отчеты → Продукт → События**.
2. Сверху выберите период: «Сегодня», «Вчера», «Неделя», «Месяц», «Квартал» или свои даты.
3. В таблице найдите событие по названию. Над таблицей есть поле поиска.
4. Чтобы увидеть параметры события, в настройке «Группировка» оставьте «Событие» с пунктом «Все параметры» (уровни 1–5). Чтобы разбить события по одному параметру (например, по способу входа `method`), добавьте группировку «Параметр» и выберите его. Доступны параметры первого уровня, а у наших событий все параметры такие.
5. Полезные кнопки:
   - **Сегмент** — оставить только часть пользователей;
   - **Сравнение** — сравнить с другим периодом;
   - **Метрики** — выбрать, что считать: события, пользователи, событий на пользователя;
   - **По 10 минут** — шаг графика, его можно сделать крупнее.
6. «Нет данных для выбранного периода» значит, что событий не было, период слишком мал или данные ещё не дошли.

## Другие отчёты

Все они в разделе **Отчеты**.

| Раздел | Что смотреть |
|--------|--------------|
| Продукт | События, Воронки, Retention-анализ (возвращаемость), Когортный анализ, Вовлеченность, Аудитория |
| Технологии | Версии приложения, Операционные системы, Модели устройств, Язык интерфейса |
| Маркетинг | Установки, конверсии, Push-кампании |
| Крэши и ошибки | Сбои приложения |
| Монетизация | Доходы и покупки (пока не используется) |

**Воронки** (Продукт → Воронки) показывают, сколько пользователей проходят цепочку шагов и где отваливаются. Что стоит построить:

- вход: `auth_method_picked` → `login` или `sign_up`;
- запись: `appointment_created` → `appointment_confirmed` → `appointment_completed`;
- подписка: `subscription_checkout_started` → оплата (успешная оплата пока не отслеживается).

**Профили.** После входа пользователь привязывается к своему ID в Slotter. Список: Отчеты → Популярные → Список профилей. Состояние платных каналов мастера записывается в его карточку, подробности в разделе «Состояние платных каналов в профилях».

**Настройка** нужна редко: основные данные приложения, выдача доступов коллегам. Изменения применяются сразу, поэтому без необходимости ничего не меняйте.

## Какие события есть в приложении

В отчётах события называются так, как в первой колонке.

**Вход и регистрация**

| Событие | Что означает |
|---------|--------------|
| `auth_method_picked` | пользователь выбрал способ входа |
| `auth_code_failed` | код не подошёл, истёк или не пришёл |
| `auth_fallback_to_call` | пользователь переключился на подтверждение звонком |
| `login` | успешный вход |
| `sign_up` | зарегистрирован новый аккаунт |
| `password_reset` | пароль успешно сброшен |
| `onboarding_step` | пройден шаг знакомства с приложением |

Параметры, по которым события можно разбивать:

- `method` — способ входа: `password` (по паролю), `telegram` (код из Telegram), `flashcall` (входящий звонок, нужно ввести последние цифры номера), `callback` (пользователь сам звонит на указанный номер);
- `flow` — что происходит: `login` (вход), `reset` (сброс пароля);
- `reason` — причина ошибки кода: `wrong_code` (неверный), `expired` (истёк), `deactivated` (деактивирован), `timeout` (не дождались);
- `step` — название шага знакомства с приложением.

**Записи**

| Событие | Что означает |
|---------|--------------|
| `appointment_created` | запись создана |
| `appointment_confirmed` | запись подтверждена |
| `appointment_arrived` | клиент пришёл |
| `appointment_completed` | запись выполнена |
| `appointment_cancelled` | запись отменена |
| `appointment_rescheduled` | запись перенесена |
| `appointment_missed` | клиент не пришёл |

**Подписка**

| Событие | Что означает |
|---------|--------------|
| `subscription_checkout_started` | пользователь начал оформлять подписку (параметр `price_id` — выбранный тариф) |
| `subscription_cancel` | подписка отменена |

## Состояние платных каналов в профилях

У мастеров платной редакции в карточку профиля записывается состояние каналов уведомлений клиентов: Telegram, MAX и WhatsApp. Так в «Профили» можно найти, например, всех, у кого оплата канала просрочена, или посчитать, сколько мастеров подключили WhatsApp.

**Атрибуты уже заведены** в AppMetrica: Настройка → Атрибуты профилей → «Собственные атрибуты». Их названия и типы (в кабинете типы подписаны `string`, `number`, `bool`):

| Название | Тип | Что означает |
|----------|-----|--------------|
| `direct_telegram_status` | строка (`string`) | состояние Telegram-канала |
| `direct_telegram_days_left` | число (`number`) | дней до конца оплаченного периода |
| `direct_max_status` | строка (`string`) | состояние MAX-канала |
| `direct_max_days_left` | число (`number`) | дней до конца оплаченного периода |
| `direct_whatsapp_status` | строка (`string`) | состояние WhatsApp-канала |
| `direct_whatsapp_days_left` | число (`number`) | дней до конца оплаченного периода |
| `direct_has_problem` | да/нет (`bool`) | хотя бы у одного канала есть проблема |

Пока атрибут не получил первое значение, в кабинете у него статус «Не собирается». Это нормально: статус сменится, когда первый обновившийся мастер откроет приложение и данные дойдут.

Названия в кабинете и в приложении должны совпадать буква в букву, иначе значения не соберутся. Кнопка «В архив» прекращает сбор по атрибуту, и он пропадает из всех отчётов, поэтому без необходимости её не нажимайте. Всего можно завести до 100 собственных атрибутов.

**Значения состояния:**

| Значение | Что это |
|----------|---------|
| `not_connected` | канал не подключён |
| `active` | канал работает |
| `connecting` | оплачен, но ещё подключается |
| `pending_payment` | оплата не завершена |
| `grace` | оплата просрочена, нужна оплата |
| `awaiting_auth` | ждёт привязки аккаунта |
| `reconnect` | нужно переподключить |
| `lost` | канал отключился, подписка потеряна |
| `failed` | ошибка подключения |
| `cancelled` | подписка отменена |
| `expired` | подписка закончилась |

«Проблема» (`direct_has_problem`) — это состояния `grace`, `reconnect`, `lost`, `failed`. Дни до конца оплаты показываются только у действующих подписок, у остальных поле пустое.

**Как смотреть.** Откройте «Профили» и отфильтруйте по нужному атрибуту, например `direct_has_problem` = да или `direct_whatsapp_status` = `grace`. Эти же условия можно использовать как сегмент в других отчётах.

**Что учитывать:**
- данные приходят с телефона мастера: пока он не обновил приложение и не открыл его, его нет в этих срезах;
- состояние обновляется при запуске приложения и когда канал меняется (например, активируется);
- число дней обновляется в те же моменты, а не каждый день;
- у мастеров без платной редакции этих полей нет.

## Что учитывать

- **Сбои приложения (крэши)** отслеживаются отдельной системой, поэтому отчёты «Крэши и ошибки» в AppMetrica пустые.
